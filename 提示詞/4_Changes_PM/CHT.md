主題：

# PM 的四個轉變：從需求管理到決策設計

副標：
AI 可以幫忙展開需求，但不能替團隊決定「為什麼做、做到哪裡、什麼才算對」。

整體風格：
白底、企業內訓、顧問式資訊圖、深藍為 PM 主色。
大量留白、細線、圓角矩形、扁平化 Vector Icon。
2×2 四卡布局，四張卡大小完全一致。
每張卡都使用：
編號 → 轉變標題 → BEFORE → 箭頭 → AFTER → 一句 Key Message。
不要照片、不要 3D、不要卡通。

【01】
從收需求 → 定義問題與價值

BEFORE：
User 要什麼？
收需求 / Feature / Backlog

AFTER：
為什麼值得做？
Problem
Goal
User Value
Outcome

Key Message：
先確認問題，再討論 Solution。

【02】
從寫需求 → 定義邊界與判準

BEFORE：
描述功能
「系統會自動調整室溫」

AFTER：
定義什麼才算做對
Trigger
Boundary
State
Exception
Timing
Acceptance Criteria

Key Message：
不是把需求寫得更長，而是把決策空白變少。

【03】
從追進度 → 建立決策與需求治理

BEFORE：
Task %
Deadline
Jira Status
Meeting Follow-up

AFTER：
Decision Log
Requirement Traceability
Change Control
Ownership
Priority / Trade-off

Key Message：
從追「做了多少」轉向管理「為什麼這樣決定」。

【04】
從需求看似清楚 → 尋找假設與盲點

BEFORE：
Requirement Complete
大型綠色勾勾

AFTER：
主動尋找 Hidden Assumptions

畫面呈現三個問題泡泡：
「一定登入？」
「一定有網路？」
「一次只有一人操作？」

旁邊加入問號、放大鏡、盲區 icon。

Key Message：
需求最大的風險，常藏在沒有人寫下來的假設裡。

【底部總結】
PM 的核心價值：
決定「什麼叫對」。

Goal / Scope / Boundary / Priority / Acceptance Criteria / Trade-off

注意：
視覺不要像四個普通 bullet。
必須明確表現四個 BEFORE → AFTER 的角色轉變。
