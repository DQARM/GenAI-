主題：

# QA 的四個轉變：從執行測試到設計風險控制

副標：
AI 可以大量產生案例與執行測試；QA 更重要的工作，是決定哪些風險必須被看見、什麼證據才足以相信。

整體風格：
白底、企業內訓、顧問式資訊圖。
紫色／藍紫色作為 QA 主色。
2×2 四卡布局，與 PM、RD 系列頁完全相同。
使用扁平 Vector Icon、細線、圓角卡片、大量留白。
不要照片、不要 3D、不要卡通。

【01】
從測功能 → 測風險

BEFORE：
確認功能有沒有做對
Checklist + Magnifier

AFTER：
尋找：
Specification Gap
Wrong Assumption
Security Risk
Failure Scenario

使用缺口拼圖、問號、盾牌、警告 icon。

Key Message：
不只問「做對了嗎」，還要問「漏了什麼」。

【02】
從寫案例 → 設計判準（Oracle）

BEFORE：
大量 Test Cases
很多文件 icon

AFTER：
設計：
Expected Result
Acceptance Criteria
Invariant
Independent Verification Evidence

使用靶心、裁判／天平、檢核表、盾牌 icon。

Key Message：
關鍵判準不能只由產生 Code / Test 的同一來源決定。

【03】
從手動執行 → 建立驗證系統

BEFORE：
人力執行測試

AFTER：
Automation Gate
Observability
Regression Strategy
Continuous Verification
Review Flow

使用 Gate、監控螢幕、循環箭頭、Pipeline icon。

Key Message：
從「人肉跑測試」轉向「系統持續提供驗證證據」。

【04】
從全綠安心 → 尋找驗證盲區

BEFORE：
100% PASS
大型綠色勾勾

AFTER：
主動尋找：
Unknown
Abnormal
Adversarial
Missing Assertion
Requirement Blind Spot

使用問號、Bug、警告、駭客、盲區等 icon。

Key Message：
全過只證明被問過的問題沒出錯，不代表沒有問題。

【底部】
QA 的核心價值：

證明「我們憑什麼相信它是對的」。

Risk / Oracle / Verification Evidence / Blind Spot / Release Criteria
